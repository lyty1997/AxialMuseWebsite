# 变更任务工作流

## 执行顺序

1. 检查工作区、相关设计、现有实现和配置，区分用户已有改动与本次任务范围。
2. 应用根目录 `AGENTS.md` 的用户决策门禁；存在未确认事项时，停止依赖该事项的文档、实现、Git 和外部操作。
3. 用户确认后，以下变化先更新对应设计或决策记录，再实现：
   - 页面结构、导航、路由、内容栏目或 SEO；
   - 产品服务、收费、订阅、评论、讨论或反馈入口；
   - 用户数据、分析、表单、第三方脚本或浏览器外部请求；
   - 部署、框架、依赖策略、CMS、后端服务或数据库。
4. 小步完成最小可验证闭环。不为交付速度引入无依据的复杂度或掩盖失败的多余兜底；暴露真实错误并处理根因。
5. 运行项目已有且与改动匹配的格式化、lint、typecheck、测试或 `npm run quality`；UI 改动还须实际渲染或截图。无法验证时说明原因与风险。

## 决策说明

需要用户选择时，依次给出：要解决的问题；已知事实与来源；不确定项；通常 2-3 个可行且互斥的方案；各方案的收益、成本、风险、维护责任和可逆性；推荐及理由；确认前暂停的操作。明确等待用户选择。

## 交付说明

汇报修改文件、验证结果、遗留或待确认项，以及是否新增第三方服务、浏览器外部请求或用户数据处理。
