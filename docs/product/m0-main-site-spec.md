# M0 主站实现 Spec

状态：ready-for-review
最近更新：2026-07-13
适用范围：`https://www.axialmuse.com/` 首版单页主站
实现前置：本 Spec 经评审确认，项目视觉素材通过公开性检查

## 目的

本文把[主站体验与内容架构](site-experience.md)转化为可直接开发和验收的页面级规格。它定义 M0 的页面结构、公开内容、视觉系统、组件行为、响应式规则、资源约束和完成标准；技术实现与部署分别受[M0 技术选型决策](../architecture/technology-selection.md)和[域名与生产发布设计](../operations/domain-deployment.md)约束。

本 Spec 不批准生产上线。服务器、DNS、证书、备案页脚和自动发布完成独立验收后，主站才能公开。

## 成功标准

- 首次访问者在第一屏看到“Axial Muse”，并理解这是以个人项目为线索的技术分享主站。
- 访问者能在一次滚动内看到真实项目证据，并能进入两个公开 GitHub 仓库。
- 页面准确表达“当前可用、正在整理、未来探索”，不把计划能力写成已经上线。
- 站点在手机、平板和桌面端可阅读、可键盘操作，无重叠、横向滚动或布局跳动。
- 页面不采集访问者数据，不加载第三方运行时资源，不提供尚未批准的项目体验入口。

## 非目标

- 不建设营销落地页、个人简历、内容后台或通用内容门户。
- 不增加项目详情页、文章详情页、站内搜索、标签筛选或分页。
- 不增加登录、评论、订阅、反馈表单、支付、访问分析或 Cookie。
- 不创建 `docrestore.axialmuse.com`，也不展示“在线体验”按钮。
- DocRestore 演示视频不阻塞主站首版；素材完整前不出现播放器或占位入口。
- 不在 M0 引入前端框架、组件库、图标库、CMS 或运行时 API。

## 页面地图

M0 只有一个可索引页面和四个稳定锚点：

| 区域 | URL | 导航名称 | 目的 |
|---|---|---|---|
| 首页 | `/` | 品牌链接 | 回到页面顶部 |
| 项目 | `/#projects` | 项目 | 展示真实项目、取舍和公开证据 |
| 技术分享 | `/#writing` | 技术分享 | 准确展示首批内容尚在整理 |
| 路线 | `/#roadmap` | 路线 | 区分当前、下一步和探索方向 |
| 关于 | `/#about` | 关于 | 说明作者关注方向和公开 GitHub 入口 |

页脚不进入主导航。品牌链接使用 `/`，页面内导航使用同页锚点；不使用 `./index.html` 作为公开 canonical 链接。

## 访问路径

首版支持三条主要路径：

1. 首次访问：品牌与定位 -> 浏览项目 -> 查看仓库。
2. 从项目仓库返回：定位 -> 项目取舍与状态 -> 路线或关于。
3. 搜索进入：首页元数据 -> 项目证据 -> 确认内容状态与公开身份。

页面只有一个主动作“浏览项目”。项目区动作按内容存在性显示“查看源码”或“观看演示”；当前两个项目只显示“查看源码”。

## 页面结构

### 跳过导航

- `body` 的第一个可聚焦元素是“跳到主要内容”。
- 默认移出可视区域，键盘聚焦时显示在左上角。
- 目标是 `main` 的稳定 `id`，不能只依赖 JavaScript。

### 页头

- 左侧展示文本品牌“Axial Muse”，链接到 `/`。
- 右侧导航固定为“项目、技术分享、路线、关于”。
- 页头不吸顶，避免在小屏持续占用阅读空间。
- 桌面端单行排列；空间不足时允许自然换行，不使用汉堡菜单或隐藏导航。
- 导航 hover 和 focus 必须有非颜色之外的可见反馈，例如下划线。

### 首屏介绍

- H1 必须是品牌名“Axial Muse”，不把描述性口号作为品牌标题。
- 支持文案明确表达“围绕个人项目，记录设计、实现、技术取舍与复盘”。
- 当前阶段文案说明首版先公开项目与工程记录，不宣称产品服务已上线。
- 主动作“浏览项目”链接到 `#projects`。
- 介绍区不是满屏封面；在 800-900 px 高的常见视口中必须露出项目区标题或首张项目图的一部分。
- 介绍内容不放进卡片，不使用渐变、装饰性光斑、通用图库图或与项目无关的背景图。

### 项目区

项目区从 `docs/contracts/projects.json` 获取公开事实。首版按以下顺序展示：

| 顺序 | 项目 | 展示模式 | 允许动作 | 禁止动作 |
|---:|---|---|---|---|
| 1 | DocRestore | 项目说明 + 真实界面证据 | 查看源码；素材齐全后可观看演示 | 在线体验、试用、上传文件 |
| 2 | VibeCoding Project Scaffold | 项目说明 + 真实工程证据 | 查看源码 | 在线体验、下载服务、演示占位 |

每个项目条目包含：

- 16:10 视觉区域，使用真实截图或工程证据，固定宽高比避免布局跳动。
- 项目名称、生命周期状态、最近实质更新时间。
- 一句话问题摘要，不使用“革命性”“领先”等不可验证营销词。
- 2-3 条关键取舍，内容来自项目契约和对应项目设计文档。
- 明确的公开动作；GitHub URL 必须与项目契约完全一致。
- 在线体验仅在体验注册表为 `live` 且健康检查通过时显示。M0 当前没有满足条件的项目。

视觉区域是项目条目的一部分，不嵌套额外卡片。DocRestore 建议使用已脱敏的处理流程结果界面；Project Scaffold 建议使用初始化后目录、质量门禁输出或文档入口的真实组合截图。终端截图必须裁掉用户名、主机名、绝对路径、远端地址和凭证。

项目 contract 的 `publicationStatus` 在内容、链接和视觉素材通过审核后才能改为 `published`。生产页面不得展示 `draft` 或 `planned` 项目；本地评审页面如临时展示，必须明确标记且不能进入 `main` 生产 release。

### 技术分享区

- 首版没有正式文章时，显示一个简短、真实的空状态，不列出虚构标题或“即将上线”时间。
- 建议文案：“技术分享正在从项目记录中整理。首批内容发布后会在这里提供可核验的原始资料与实现细节。”
- 空状态使用普通文本和分隔线，不制作成装饰性卡片，不显示不可点击的按钮。
- 第一篇文章达到 `published` 后，本区改为文章列表；该改动必须先补充内容契约和 URL 设计。

### 路线区

路线使用三个并列阶段，描述范围而非承诺日期：

| 阶段 | 标题 | 可公开内容 |
|---|---|---|
| 当前 | 建立可信主站 | 项目资料、页面基线、域名上线与自动维护 |
| 下一步 | 形成技术分享 | 从已完成项目提炼可复盘文章，并保持证据链接 |
| 探索 | 产品服务 | 只有服务边界、隐私和支持方式明确后才提供入口 |

阶段在桌面端可以三列展示，在移动端按顺序堆叠。它们是同一内容序列，不使用三张悬浮营销卡。

### 关于区

- 说明作者关注 AI 工程、知识工作流、开发规范和个人产品构建。
- 明确本站公开的是项目、技术取舍和复盘，不公开私人联系方式、凭证或私有仓库。
- 提供 GitHub 个人主页 `https://github.com/lyty1997`，动作名称为“查看 GitHub 主页”。
- 不展示技能百分比、客户 Logo、虚构评价、社交关注数或不可验证履历。

### 页脚

- 展示品牌名、当前年份和 ICP 备案号 `沪ICP备2026029086号`。
- ICP 备案号链接到 `https://beian.miit.gov.cn/`。
- 备案信息在桌面和移动端都可见，不用低对比度弱化到难以阅读。
- 公安联网备案号在完成核验前不显示占位文本。

## 视觉系统

### 方向

界面应像安静、可重复使用的工程作品索引：以真实项目证据、清楚的内容层级和紧凑导航为中心。避免营销式大面积口号、装饰性卡片堆叠、渐变背景、模糊光斑、过量阴影和单一色相铺满页面。

### 设计令牌

实现阶段以 CSS Custom Properties 建立以下最小令牌；在对比度实测前允许小幅调整数值，但不能临时增加大量近似颜色。

| 类别 | 令牌 | 基线值 | 用途 |
|---|---|---|---|
| 背景 | `--color-canvas` | `#f4f6f3` | 页面底色 |
| 表面 | `--color-surface` | `#ffffff` | 项目条目视觉和必要表面 |
| 主文本 | `--color-ink` | `#171a1c` | 标题与正文 |
| 次文本 | `--color-muted` | `#596168` | 辅助说明 |
| 边线 | `--color-line` | `#cfd6d1` | 分隔和边框 |
| 主强调 | `--color-accent` | `#0b6b5f` | 主动作、焦点和当前状态 |
| 次强调 | `--color-signal` | `#b94b35` | 少量阶段或证据标记 |
| 深色带 | `--color-dark` | `#1d2528` | 页脚或单个对比内容带 |
| 反白文本 | `--color-on-dark` | `#f7faf8` | 深色带文字 |

颜色使用中性背景、绿色主强调和陶红次强调形成可辨层级，不能把整个页面做成绿色或深蓝色的单色主题。状态不能只靠颜色表达。

### 字体与字号

- 字体使用系统无衬线栈；不加载远程字体。
- 正文基线 16 px，行高 1.65；长说明最大行宽约 70 个中文字符。
- 桌面 H1 64 px、H2 36 px、H3 22 px；移动 H1 42 px、H2 30 px、H3 21 px。
- 字号只在明确媒体查询中切换，不使用 `vw` 或随视口连续缩放。
- 所有文本 `letter-spacing: 0`；英文大写标签不通过负字距压缩。

### 间距与尺寸

- 间距尺度：4、8、12、16、24、32、48、64、96 px。
- 页面内容最大宽度 1200 px，正文列最大宽度 720 px。
- 项目视觉统一 `aspect-ratio: 16 / 10`，不得因图片加载或状态标签改变条目尺寸。
- 卡片圆角最大 8 px；按钮或链接样式圆角最大 6 px，不使用胶囊形大按钮。
- 章节使用全宽分隔带或边线，不把每个章节包进浮动卡片。
- 阴影只在确有层级需求时使用一个低强度令牌，默认不用阴影。

## 响应式规格

| 视口 | 布局要求 |
|---|---|
| 360-479 px | 单列；页头换行；项目图占满内容宽；动作可换行但点击区至少 44 px 高 |
| 480-767 px | 单列；适度增加左右留白；路线按顺序堆叠 |
| 768-1023 px | 项目仍可单列或进入两列，以文本不拥挤为准；导航保持完整可见 |
| 1024 px 以上 | 两列项目网格；路线三列；内容容器不超过 1200 px |

必须在 320 px 宽度下保持核心内容可读，不出现页面级横向滚动。超长仓库名、中文和英文混排应自然换行；不能通过缩小到不可读字号解决溢出。

浏览器验收覆盖仍在安全更新期的主流实现，不依赖厂商私有能力：

- Chromium 系浏览器当前和上一主版本。
- Firefox 当前和上一主版本。
- macOS/iOS Safari 当前和上一主版本；无实体设备时可用 WebKit 自动化补充，但必须记录局限。

## 交互与状态

### 链接

- 主动作、项目动作和 GitHub 入口使用清楚的文本链接或图标加文本，不用仅图标表达未知动作。
- hover、focus-visible 和 active 状态都要可见；focus ring 与背景达到可辨对比度。
- 外部链接不强制新窗口。若实现选择新窗口，必须同时说明行为并使用 `rel="noopener noreferrer"`。

### 内容状态

| 状态 | 页面行为 |
|---|---|
| 项目 `planned` | 生产页面不展示 |
| 项目 `published` | 展示项目条目与已经审核的动作 |
| 视频素材不完整 | 完全不渲染播放器和观看按钮 |
| 体验非 `live` | 不渲染在线体验入口 |
| 技术分享为空 | 显示真实空状态，不制造文章标题 |
| 图片加载失败 | 保留稳定尺寸并显示有意义的替代文本，核心项目文字仍可用 |

页面没有异步数据请求，因此不设计骨架屏、加载动画、Toast 或客户端错误弹窗。

## 素材契约

每个首版项目至少需要一张真实视觉证据后才能进入生产：

| 资源 | 格式 | 尺寸建议 | 大小目标 | 审核要求 |
|---|---|---:|---:|---|
| 项目预览图 | WebP，必要时 PNG | 1600 x 1000 | <= 300 KB | 无凭证、真实隐私、绝对路径、通知和未授权内容 |
| Open Graph 图 | WebP 或 JPEG | 1200 x 630 | <= 300 KB | 品牌和文字在分享裁剪下可辨，不含计划能力 |
| favicon | SVG 或 PNG/ICO | 多尺寸 | <= 50 KB | 简单、高对比、无外部字体依赖 |
| DocRestore 视频封面 | WebP | 1600 x 900 | <= 250 KB | 与最终视频一致，逐帧审核完成后使用 |

推荐目录：

```text
public/
├── assets/
│   ├── brand/
│   │   ├── favicon.svg
│   │   └── social-card.webp
│   └── projects/
│       ├── docrestore-preview.webp
│       └── project-scaffold-preview.webp
├── index.html
└── styles.css
```

资源文件名使用小写 ASCII 和连字符。生产 HTML 不引用仓库外的图片 URL，避免第三方可用性、跟踪和防盗链问题。

## 可访问性

- 使用一个 H1，章节标题按 H2、项目标题按 H3 递进，不跳级表达视觉大小。
- `header`、`nav`、`main`、`footer` 和各 `section` 具有明确语义或可访问名称。
- 所有功能可用键盘完成；页面顺序与视觉顺序一致。
- 正文、次文本、链接、焦点和状态在最终颜色上达到 WCAG 2.2 AA 对比度目标。
- 项目截图的替代文本说明它证明的界面或工程状态，不重复标题；纯装饰资源使用空 `alt`。
- 文本放大 200% 时不截断，不隐藏导航、项目动作和备案信息。
- 尊重 `prefers-reduced-motion` 和 `prefers-contrast`；核心内容不依赖动效出现。

## SEO 与分享

生产首页使用以下精确契约：

| 字段 | M0 值 |
|---|---|
| HTML | `lang="zh-CN"`、UTF-8、正确 viewport |
| `title` | `Axial Muse | 个人项目与技术分享` |
| `description` | `Axial Muse 记录个人项目的设计、实现、技术取舍与复盘，公开可核验的源码与工程资料。` |
| canonical | `https://www.axialmuse.com/` |
| `og:type` | `website` |
| `og:title` | 与 `title` 一致 |
| `og:description` | 与 `description` 一致 |
| `og:url` | 与 canonical 一致 |
| `og:image` | `https://www.axialmuse.com/assets/brand/social-card.webp` |
| favicon | `/assets/brand/favicon.svg` |
| `robots.txt` | `/robots.txt`，允许抓取生产首页 |
| `sitemap.xml` | `/sitemap.xml`，只列 canonical 首页 |
| 正文公开链接 | GitHub 主页、两个项目仓库和 ICP 备案查询 |

`robots.txt` 内容基线：

```text
User-agent: *
Allow: /
Sitemap: https://www.axialmuse.com/sitemap.xml
```

`sitemap.xml` 只包含 `https://www.axialmuse.com/`，并在内容实质更新时同步 `lastmod`；不包含锚点、预览 URL 或不存在的项目体验。

预览环境必须通过 HTTP 响应头或页面元数据阻止索引，不能把预览 URL 写入 canonical、站点地图或公开内容。

## 性能与资源请求

- 首页关键内容不依赖 JavaScript 执行。
- 不加载第三方字体、分析、广告、视频 iframe 或社交组件。
- 首屏外项目图片使用 `loading="lazy"` 和 `decoding="async"`；首个可见项目图根据实际 LCP 测试决定是否延迟。
- 图片声明固有宽高；CSS 对项目视觉使用稳定比例。
- 不包含视频时，首次加载总传输量目标 <= 1.5 MB，单张图片目标 <= 300 KB。
- 发布前检查浏览器控制台无 404、混合内容、HTML 解析和 CSS 资源错误。

## 数据映射

`docs/contracts/projects.json` 与页面的最低映射如下：

| Contract 字段 | 页面位置 | 门禁要求 |
|---|---|---|
| `id` | 项目条目标识或可追踪属性 | 唯一，且只允许已知项目 |
| `title` | H3 | 必须完全一致 |
| `summary` | 项目摘要 | 不得扩张为未验证承诺 |
| `status` | 状态文本 | 使用用户可理解的中文映射 |
| `updatedAt` | 最近更新 | 日期必须完全一致 |
| `decisions` | 关键取舍 | 展示 2-3 条，不改变事实含义 |
| `repositoryUrl` | 查看源码 | href 必须完全一致且为 HTTPS |
| `showcaseMode` | 动作集合 | 决定是否允许视频入口 |
| `onlineExperience` | 在线体验 | `false` 时页面不得出现该入口 |
| `publicationStatus` | 是否生产展示 | 只有 `published` 可以出现 |

M0 实现时扩展 `scripts/quality/check-static-site.mjs` 和 `docs/contracts/site-checks.json`，至少自动校验导航锚点、canonical、备案号、两个项目仓库、禁止的在线体验入口和本地资源存在性。

## 实施顺序

1. 内容准备：确认两个项目摘要、取舍、更新时间和公开仓库事实。
2. 素材准备：生成真实截图，完成隐私和版权检查并压缩。
3. 结构实现：先完成语义 HTML、锚点、内容状态和元数据。
4. 视觉实现：按令牌、布局、响应式和交互状态完成 CSS。
5. 门禁实现：更新站点检查，确保页面与项目契约一致。
6. 浏览器验收：完成桌面、平板、手机截图与键盘、缩放、资源检查。
7. 生产准备：服务器加固、Nginx、证书、TAT 发布和回滚演练。
8. 域名上线：DNS、HTTPS、备案、公开冒烟和 24 小时观察。

步骤 1-6 在 `dev` 和 PR 上完成；只有评审与 required checks 通过后才合入 `main`。步骤 7-8 不与页面开发混在同一个不可回滚操作中。

## Definition of Done

### 内容与功能

- 页面严格包含页头、首屏介绍、项目、技术分享、路线、关于和页脚。
- 导航固定为“项目、技术分享、路线、关于”，所有锚点可用。
- DocRestore 与 VibeCoding Project Scaffold 的标题、摘要、取舍、日期和仓库链接与 contract 一致。
- 没有 DocRestore 在线体验入口；视频素材不完整时没有播放器或观看入口。
- 技术分享没有虚构文章标题；路线没有承诺发布日期。
- GitHub 个人主页和 ICP 备案链接正确可访问。

### 视觉与浏览器

- 360 x 800、768 x 1024、1440 x 900 三个视口完成截图并人工检查。
- 第一屏显示品牌、定位和主动作，并露出下一章节内容。
- 没有文字重叠、溢出、不可解释空白、页面级横向滚动或动态布局跳动。
- 项目视觉是真实、清晰、已脱敏的证据；页面不使用渐变、装饰光斑或通用图库图。
- 键盘顺序、焦点、200% 文本缩放和 reduced motion 验收通过。

### 工程与发布准备

- `npm run quality` 通过，新增站点契约覆盖本 Spec 的关键事实。
- HTML、CSS 和本地资源在浏览器控制台没有错误或 404。
- 页面无第三方运行时请求、Cookie 和站点自有 JavaScript。
- canonical、Open Graph、favicon、`robots.txt` 和 `sitemap.xml` 一致。
- `public/` 可由静态 HTTP 服务和 Nginx 直接提供，不依赖构建命令。
- PR 描述附桌面与移动截图、质量结果、对应设计文档和未完成素材说明。
