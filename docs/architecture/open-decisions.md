## 依 D-078 形成的 M0 工程决定

- **E-001 / 2026-07-18 — 项目内容职责拆分**：`docs/contracts/projects.json` 继续拥有项目 ID、短 slug、标题、摘要、状态、日期、仓库、展示开关、导航顺序和写作模块等结构化事实；项目长文位于 `site-content/projects/<project-id>/index.md` 或 `index.mdx`，只拥有背景、能力、取舍、限制、证据说明和复盘正文，不重复 H1、摘要、状态、日期、仓库或路由字段。构建期根据稳定 project ID 关联两者，并从注册表只读派生 Docusaurus 的 `title`、`description`、完整 `/projects/<project-slug>` 路径和草稿行为，不回写源文件。`published` 或 `archived` 项目必须恰有一个正文入口；`draft` 或 `planned` 可以暂缺正文但不能产生生产路由；孤儿正文、双入口和结构化字段双写均使构建失败。项目列表、项目侧栏和详情元数据读取同一注册表，正文文件路径不生成公开 URL。
- **E-002 / 2026-07-18 — URL 与路由闭包**：站点显式使用 `trailingSlash: true`；文章源 `slug` 和项目注册表短 slug 均不保存末尾 `/`，Docusaurus 构建链接与 canonical 统一输出末尾 `/`，Nginx 将无末尾斜杠的页面请求永久重定向到规范地址。Docusaurus `onDuplicateRoutes`、断链和锚点检查使用失败关闭；构建门禁在规范化后统一比较 `src/pages`、docs、静态资源和重定向。首版内容路由只允许 `/`、`/projects/`、`/projects/<project-slug>/`、`/writing/` 与已发布 `/writing/<article-slug>/`；`/assets/`、`/img/`、`/.well-known/`、`/404.html`、`/robots.txt` 和 `/sitemap.xml` 为框架或运维保留空间。重定向登记只接受同站精确旧路径到精确新路径，禁止通配、链、环、自重定向和与活动路由冲突；系列、主题、作者、归档、筛选、分页、RSS 与独立 `/about/` 路由不进入 M0。Docusaurus 对 [`trailingSlash` 和 `onDuplicateRoutes` 的官方配置语义](https://docusaurus.io/docs/api/docusaurus-config)是本决定的框架依据。
- **E-003 / 2026-07-18 — 内容注册表与发现关系**：作者注册表使用 `docs/contracts/authors.json` 的对象型 ID 映射，GitHub 链接对新增作者可选；受控主题使用 `docs/contracts/topics.json` 的对象型 ID 映射；项目写作模块嵌套在对应 `projects.json` 项目的 `writingModules` 中，并由 `(project ID, module ID)` 唯一定位。无项目文章进入只存在于导航投影中的“通用技术”分组，不伪造项目 ID。跨项目关系使用可选 `relations.projects` 稳定项目 ID 列表，只提供相关入口，不改变规范侧栏归属；主题首版只用于元数据显示和校验，不生成主题路由。所有注册表 ID 使用 lowercase kebab-case，显示名与排序可变但 ID 不复用；未知字段、悬空引用、重复项和同级排序冲突失败关闭。
- **E-004 / 2026-07-18 — Docusaurus 页面与主题适配**：首页、`/projects/` 和 `/writing/` 使用 `src/pages/` 的严格 TypeScript 页面；项目和文章详情由单一 docs 实例提供。首版保留 classic/Infima 的语义、导航与可访问性能力，通过 `themeConfig`、`src/css/custom.css` 设计令牌和页面级 CSS Modules 完成品牌化，不引入 UI 库，不使用 eject，关闭颜色模式切换并只验收亮色。默认不 Swizzle；只有真实浏览器 fit-gap 证明 CSS 和官方扩展点无法满足既定三栏职责时，才在精确锁定版本上包装最小主题组件并增加契约测试。`>=1280px` 显示完整三栏，`996-1279px` 折叠左栏并保留右侧目录，`<996px` 将左右目录都移到正文上方的可访问折叠区。M0 不增加搜索、筛选、分页、客户端滚动高亮或文章专属交互。
- **E-005 / 2026-07-18 — 静态构建与制品交付**：Docusaurus 使用默认 `build/` 输出目录，只在 GitHub Actions 对 `main` 的精确 `GITHUB_SHA` 运行冻结安装、质量、类型、静态构建和制品检查；生产服务器不安装 Node/npm、不拉取源码、不执行仓库脚本。通过门禁后，按 CODE-015 把 `build/` 复制为 artifact 的 `payload/`，并附精确提交标识和逐文件 SHA-256 metadata；固定 TAT command 只接收 workflow run/artifact 标识、提交 SHA 与预期摘要。服务器从固定仓库读取 artifact 元数据，验证其 `head_sha`、摘要、归档路径安全和内部文件清单后，只把已验证 `payload/` 安装到 `releases/<sha>`，本机冒烟通过才原子切换 `current`，metadata 不进入 Web Root。公开仓库使用无需凭证的读取路径；私有仓库仅使用限于单仓库 `Actions: read` 的细粒度凭证，仓库可见性与方案能力在 OD-009 现场核验后选择对应分支。GitHub 官方说明 [artifact v4 不可变且上传会返回 SHA-256 digest](https://docs.github.com/en/actions/tutorials/store-and-share-data)，[REST 下载端点返回短时重定向且细粒度令牌需要 `Actions: read`](https://docs.github.com/en/rest/actions/artifacts?apiVersion=2022-11-28)；具体 Action 版本与 commit SHA、凭证创建、TAT/服务器配置仍须按原门禁准入和操作授权。
