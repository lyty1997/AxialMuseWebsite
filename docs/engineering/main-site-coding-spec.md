## 编码规则

### CODE-001 真相源依赖

- 已有机器契约的领域常量、枚举和注册信息必须由实现直接消费；只有设计文档的规则必须在单一实现所有者中编码，并由契约测试引用对应 D-xxx，不得在组件、适配器和测试 fixture 中分别复制。
- 测试可以构造最小样例，但断言必须引用对应 D-xxx 或契约文件，不能把 snapshot 变成新的领域真相源。
- 构建制品、缓存和派生索引不得反向写入领域内容；获批索引必须能从当前源内容重建。

来源：D-028、D-055、D-059、D-060、D-064；[主站目标架构](../architecture/main-site-target-architecture.md)。

### CODE-002 逻辑分层与依赖方向

目标实现按职责分成以下逻辑层，并使用 D-075 确认的首版物理映射：

| 逻辑层 | 首版物理位置 | 负责 | 不得负责 |
|---|---|---|---|
| 领域核心 | `src/domain/` | 文章成员判断、领域校验、投影、分类和可见性等确定性规则 | 文件写入、网络、React、Docusaurus 生命周期、进程退出 |
| 构建适配 | 根 `docusaurus.config.ts`、根 `sidebars.ts`、`src/build/` | 文件读取、frontmatter/Docusaurus 回调、配置、本地插件和领域核心装配 | 复制领域规则、修复源内容 |
| 内容解码适配 | `scripts/content/` | 以 E-013 的 Docusaurus 官方公共解析器把 Markdown/MDX 解码为结构化 frontmatter 与正文，供构建、作者和质量入口复用 | 领域 schema、Git 历史状态、文件写入、框架字段投影 |
| 展示层 | `src/components/`、`src/pages/`、`src/theme/` | React 页面、主题和组件，消费已验证的展示输入 | 直接读取源文件、调用 Node.js 文件/进程 API、保存业务数据 |
| 作者工具 | `scripts/author/` | 作者显式创建或日期操作及其文件系统事务 | 被 Git hook、CI、预览、构建或发布隐式调用 |

`src/build/` 是受版本控制的构建期源码，不是 Docusaurus 默认静态产物目录 `build/`。`site-content/` 是内容根，不属于源码模块树。`scripts/content/` 是 E-013 限定的 Node.js 结构化解码适配，不是通用共享层，也不拥有内容规则。首版不增加职责含混的通用 `shared/` 层；出现新职责时先确认归属，不能通过共享目录绕过依赖方向。

构建适配、作者工具、质量与测试等外层可以依赖稳定领域接口；展示层只消费构建适配提供的已验证展示输入，不直接读取源内容。领域核心不得反向依赖外层、框架或 UI。未来服务通过独立网络契约集成，不得成为主站领域核心的模块依赖。跨逻辑层导入必须经过被依赖模块按需建立的显式公共入口，禁止直接导入其内部文件；同一模块内部使用相对导入。没有真实跨层消费者时不创建空 `index.ts` 或占位目录。

### CODE-003 确定性与副作用

- 领域核心函数必须使用显式输入和返回值；相同输入产生相同领域结果。
- 文件系统、环境变量、进程退出、网络、系统时间和随机数必须留在明确适配边界，不得隐藏在投影、分类或页面渲染中。
- 已确认的作者日期操作和 UUIDv7 创建入口是受控例外，但仍必须通过显式调用进入，不能由构建或预览触发。
- 不得吞掉异常、把失败改为空集合或通过宽泛 fallback 继续构建；普通 I/O、配置和程序错误在适配层汇总时必须保留原始 `cause` 和上层已要求的源文件定位。唯一窄例外是 I-06 的结构化内容解析边界：第三方或注入 parser 的原始异常可能携带正文、绝对路径或秘密，公开 `ContentDecodeError` 只保留稳定 code、脱敏仓库相对路径和无堆栈的通用 `ContentDecodeCause`，不得让原始 cause 穿过该公开错误边界；这不允许改为成功、重试、空结果或无定位失败。
- 领域校验统一返回 `ValidationResult<T>`：成功为 `{ok: true, value}`，失败为 `{ok: false, issues}`。`ContentIssue` 固定包含 `code`、仓库相对 POSIX `sourcePath`、可选点分 `fieldPath` 和面向作者的中文 `message`；不得把堆栈、绝对路径或原始敏感输入写入 issue。
- `code` 使用稳定的 `CONTENT_<SUBJECT>_<REASON>` 大写下划线格式。issues 依次按 `sourcePath`、`fieldPath`、`code` 的 Unicode code point 升序排列；同一输入不得因文件系统枚举顺序产生不同输出。领域值错误聚合后一次返回，I/O、配置损坏和程序错误抛出带 `cause` 的异常，由命令入口统一格式化并以非零状态退出；I-06 内容 parser 只使用上一条记录的脱敏替代 cause。

来源：D-047、D-056、D-059、D-060、D-065、D-066。

### CODE-004 结构化输入与路径边界

- 目标领域实现处理 JSON、URL、frontmatter 和文件路径时，应使用获批的结构化解析接口，不用字符串拼接代替语义校验。
- 当前内容、Docusaurus 回调、作者入口与历史快照都必须调用 `scripts/content/frontmatter.mjs` 的 `decodeFrontMatter`。Docusaurus 回调把框架提供的 `defaultParseFrontMatter` 传入一次；独立 Node 入口使用直接候选 `@docusaurus/utils@3.10.2` 的公开 `DEFAULT_PARSE_FRONT_MATTER`。解析后再分别执行当前完整 schema 或 E-013 的历史最小身份提取，不得以逐行扫描、正则或第二个 YAML/MDX 解析器读取 articleId。
- 文章成员、schema、投影和侧栏必须消费同一份路径规范化及成员判断结果，不得各自实现近似规则。
- 内容路径统一转换为相对仓库根的 POSIX `/` 分隔形式；输入绝对路径、反斜杠、空段、`.`、`..`、NUL、控制字符或规范化后逃逸预期根目录时失败。Linux 文件名按大小写精确匹配，不做静默大小写归一化。
- `site-content/` 内拒绝符号链接；扫描器必须同时用词法 `resolve`/`relative` 和现存路径的 `realpath` 证明真实包含关系。`writing/<source-name>/` 继续遵守 D-063；项目正文目录名必须与稳定 project ID 完全一致。已进入 Git 的文章 source-name 和 E-003 稳定注册表 ID 不得被其他内容复用；当前树、工作区候选和 E-013 的 HEAD 可达历史必须调用 CODE-018 的同一身份提取与状态判定实现。
- 项目正文入口不接受 frontmatter；目录名是正文与注册表 ID 的唯一绑定。项目注册表 schema 必须把 `problem`、`decisions`、`evidence` 及其他未声明字段作为未知字段拒绝，项目正文扫描只自动拒绝可解析的 frontmatter 与 H1；正文中的普通叙事、分节标题、证据链接及其与摘要的自然语义重叠不由字符串启发式误判，是否存在不必要的文字重复由内容审查负责。
- 迁移前质量脚本中的 Markdown 字符扫描和 HTML 正则是当前有限实现，不构成目标解析方案先例。
- #26 的真实扫描器在把正文交给 Docusaurus 前建立封闭依赖图。依赖检查先按 Markdown 容器语义屏蔽 fenced code 与同一物理行内的 code span：根、blockquote 和 list 中的围栏只在同一容器继续时保持屏蔽，离开容器的当前行立即恢复检查，未闭合的行内 code span 也不能遮蔽后续行。屏蔽后的活动内容拒绝静态 `import`/`export`、MDX expression braces，以及当前空组件白名单下的原生 HTML/JSX 标签；反斜杠转义标点与代码示例不能伪造依赖或绕过活动语法检查。
- 正文同目录 `assets/` 是该 project/article 实体唯一允许的本地素材根。Markdown image 支持受控 inline（含可选 title）、full/collapsed/shortcut reference 与首个规范 definition，目标必须精确落在本实体 `assets/`，不得跨实体、外链、逃逸或携带 query、fragment、百分号、反斜杠或空白；格式不闭合时失败，不能退回 Docusaurus 自行解释。每个实际素材还必须被所属正文的上述 image 或受控 inline link 显式引用，代码区引用不计入闭包；孤儿素材由扫描器失败关闭，引用目标缺失则不能被补造或忽略，必须由随后同一候选的严格 Docusaurus 构建失败关闭。

#### I-06 内容解码与领域校验实施契约

- `scripts/content/frontmatter.mjs#decodeFrontMatter` 与同目录 `frontmatter.d.mts` 是 Markdown/MDX 的唯一结构化 frontmatter 适配；相邻的 `json.mjs#decodeJsonDocument` 与 `json.d.mts` 共同拥有注册表 JSON 解码边界。调用方必须同时给出用于解析的 `filePath` 和已脱敏的仓库相对 `sourcePath`；Docusaurus 回调显式传入并只调用一次其 `defaultParseFrontMatter`，独立入口才动态解析已冻结的 `@docusaurus/utils@3.10.2#DEFAULT_PARSE_FRONT_MATTER`。适配在领域消费前把 `frontMatter` 递归物化为只含有限 number/string/boolean/null、稠密普通 array 与 plain object 的深冻结数据快照，拒绝 accessor、symbol key、循环、过深、非 plain 值和触发异常的 Proxy trap；透明 Proxy 的读取 trap不被复制到快照。它不执行 schema、投影或文件写入；解析器缺失、抛错或非法 shape 抛出稳定 `CONTENT_FRONTMATTER_*` code、相对路径和 CODE-003 的脱敏替代 cause，不回显原文、绝对路径、原始 cause 或堆栈。JSON 适配只接受真实 `Uint8Array`，以 TypedArray 内建 brand/长度取得上限事实并复制受控字节快照，再在 `JSON.parse` 前拒绝重复对象键、非法或非规范 UTF-8、过深和非 object 根；普通 `JSON.parse` 的后项覆盖不得成为注册表语义。两份 `.d.mts` 由 E-012 的固定 `tests/build/content-decoders-types.test.ts` 以 `import type` 消费，模块门禁不得把该窄例外扩展到运行时 `.mjs` 导入或其他脚本。
- `normalizeContentPath(sourcePath)` 只接受位于 `site-content/` 的仓库相对 POSIX 路径，拒绝绝对路径、反斜杠、空段、`.`、`..`、NUL/控制字符与大小写修正。`classifyContentPath({sourcePath,isSymbolicLink,isRealPathWithinRoot})` 在该结果上唯一判定 project/article/other；两个文件系统布尔值是 #26 扫描适配以 `lstat`、词法包含和 `realpath` 包含计算的必填事实，任一不安全值由领域函数返回稳定 issue。#23 的纯领域核心不自行读取文件系统，也不把 fixture 布尔值冒充真实扫描已经接线。
- `validateProjectCatalog` 一次接收 projects/authors/topics/project-experiences 四份已解码注册表和乱序的全部项目 Markdown/MDX 候选，整批返回一个 `ProjectCatalog`；任一成员失败时结果只有 issues，不保留合法子集。四份注册表锁定各自当前 `version`、`kind`、`status: active`、`owner: AxialMuseWebsite`、精确封套字段与嵌套字段，未知字段失败。项目、作者、主题和模块 ID 使用 lowercase kebab-case；project/module/topic 同级顺序必须为不冲突的正整数。体验 ID 额外服从项目子域 slug 契约：2-32 字符、字母开头、字母或数字结尾、不在保留子域集合内，并与 `projectId` 及项目稳定 ID 精确一致。体验验证闭合 `experienceRegistryId -> experience.id -> experience.projectId`、公开 hostname/status 与当前机器契约，不因此批准 DNS 或体验上线。关系闭合使用已通过自身 ID/外键形态校验的 probe，不因同一成员的标题等无关字段无效而制造伪悬空级联；最终成功值仍只来自完整合法成员。
- 项目 schema 继续以内容模型字段表为闭集。I-06 将此前未给出机器形态的内部细节固定为：`title` 1-100、`summary` 20-200 个 grapheme；`startedAt` 只允许真实 `YYYY-MM` 或 `YYYY-MM-DD`，`updatedAt` 为真实 `YYYY-MM-DD` 且不得早于开始日期；`productionBranch` 是 1-100 字符的单行安全 Git ref、拒绝 `HEAD`，且只与规范 `https://` URL 形态的 `repositoryUrl` 成对出现；HTTPS 字段必须与 WHATWG URL 的 `href` 逐字一致，不接受隐式 scheme、反斜杠、默认端口或 origin-only 缺 `/` 等规范等价写法。`source` 为 1-10 个不重复 HTTPS URL 或不逃逸仓库的相对路径；站内根相对素材路径拒绝百分号和任意空白，避免浏览器重写后改变身份。`relatedWriting` 为 1-10 个不重复 UUIDv7 articleId，并在文章整批校验时闭合。`demoVideoStatus` 只允许 `asset-pending`、`review-pending`、`approved`；三个视频路径必须成组出现且仅在 `approved` 与 `repository-and-video` 时出现。所有单行文本拒绝首尾空白而不静默 trim。主预览只在 #23 校验对象字段、项目绑定路径、固定登记尺寸与 alt；WebP 字节、动画、实际尺寸、大小、孤儿和重复素材继续由 #6 独立验收。
- 项目正文输入包含唯一解码结果与正文；非空 frontmatter、ATX/Setext/原生 `<h1>` 标题、孤儿目录、双入口或公开项目缺正文均失败。H1 判定使用单一线性 Markdown 状态机并忽略 fenced code 内文本，不把普通问题、取舍、证据文字、H2/H3 或语义相似性误判为结构化重复。空 frontmatter 对象本身不伪造字段；畸形 frontmatter 已在解码适配失败。
- `validateArticleSource({catalog,sources})` 名称保持既定公共 API，但参数和返回值固定为整批文章源；这是 articleId/slug 唯一性、`relations.articles`、项目 `relatedWriting` 和跨文章 recommendation priority 不散落到适配层的唯一实现。每个 source 携带 `sourcePath`、结构化 frontmatter、正文及上述文件系统事实；函数稳定按 articleId 输出完整成功数组，任一文章或跨文章关系失败时不返回部分 value。UUIDv7、完整 `/writing/<lowercase-kebab-case>` slug、状态日期、作者/主题/项目/模块、关系、SEO 去重、推荐、修订和来源逐项按内容模型校验；只有原始 `relations` 确为 `{}` 或只含空 `projects|articles` array 时才报告“空关系对象或空关系数组必须省略”，超限、重复、类型错误或其他无效非空输入只保留其真实字段诊断，不能因校验结果被置空再追加伪空诊断。draft 禁止 `publishedAt` 与 `revisions`，公开状态要求两日期且 `updatedAt >= publishedAt`。`published|archived` 文章的 `classification.project`、`relations.projects` 与 `relations.articles` 只能指向同为 `published|archived` 的目标，公开项目的 `relatedWriting` 也只能指向公开文章；draft、planned 等未发布源仍可引用已经登记且通过自身 schema 的目标。重复 articleId、错误所有者或状态冲突使整个批次失败，不能借重复身份或无部分 value 语义绕过可见性闭包。所有要求 string 的日期值在 YAML 中必须写成带引号的 scalar；固定 Docusaurus parser 会把未加引号的 YAML timestamp 解码为 `Date`，该非 plain 值在结构化快照边界失败，不得静默转为 ISO 字符串。首次发布日期不可改和稳定 ID 历史不可复用仍由 #12 负责；保留路由与全站冲突由 #26 负责。
- `ValidationResult<T>` 成功精确为 `{ok:true,value}`，失败精确为 `{ok:false,issues}`。数组字段路径使用点分十进制索引，例如 `authors.0`；项目注册表到文章整批闭合阶段使用稳定逻辑定位 `projectsById.<projectId>.relatedWriting.<index>`，不把对象枚举顺序伪装成源数组索引；无字段路径按空字符串参与排序。未知或不可信 object key 不得原样进入诊断，超出安全段格式时统一定位到 `unknownField`。`ContentIssue` 以 `(sourcePath,fieldPath,code)` 为身份，同一三元组只保留一个由 code 固定的中文 message，并按三项 Unicode code point 升序；message 不参与排序。code 使用 `CONTENT_<SUBJECT>_<REASON>`，issue 不含输入值、绝对/临时路径、环境、堆栈或受限正文。领域对象按稳定 ID/路径排序并深冻结，不修复源值、不调用投影 spy、不读取时间或随机数。
- #23 的可执行关闭入口是 E-012 的同一 `npm test`：领域 TypeScript fixture 覆盖完整合法批次、乱序等价、所有约定反例与失败无 value，`.mjs` fixture 覆盖 JSON/frontmatter 唯一解码及脱敏异常。#26 再以真实扫描和 Docusaurus build 证明 I/O、realpath、整批装配与非零进程边界；#23 不以尚未接线的文件系统或零文档 build 冒充完成。

#### I-11 项目主预览媒体校验实施契约

- `validateProjectMedia({catalog,sources})` 是 E-007 的唯一纯领域媒体入口。`catalog` 必须是已经由 `validateProjectCatalog` 整批验证的 `ProjectCatalog`；`sources` 是 `site-assets/projects/` 下完整、乱序的媒体候选集合。每个候选显式携带仓库相对 POSIX `sourcePath`、`isSymbolicLink`、`isRealPathWithinRoot` 与 `isRegularFile`；#7 的扫描适配先使用 `lstat`、词法包含和 `realpath` 计算这些事实，只有已证明不是符号链接、真实路径位于素材根内且为普通文件时才读取一次并附带真实 `Uint8Array` 字节。不安全或未证明安全的候选必须省略 `bytes`，领域入口同时拒绝其文件事实和意外字节，避免扫描适配为满足 schema 而解引用根外或特殊对象。领域函数不自行读取文件系统，也不接受绝对路径或临时路径作为诊断身份。
- 候选 `sourcePath` 必须精确为 `site-assets/projects/<project-id>/<lowercase-kebab-case>.webp`；注册表登记仍只保存相对 `site-assets/` 的 `projects/<project-id>/<name>.webp`。入口把两者一对一闭合，拒绝缺失、孤儿、重复候选、重复登记、跨项目、逃逸、反斜杠、大小写漂移、符号链接、realpath 逃逸和非普通文件。任一问题都只返回排序后的 `ContentIssue[]`，不得跳过坏文件后返回合法子集。
- 安全普通文件的字节输入先用 TypedArray 内建 brand 与长度读取；超过 300,000 bytes 时在分配或复制前失败，其余才复制为受控快照。零依赖 WebP 解析器必须验证精确 RIFF/WEBP 长度、chunk 边界与 padding，并支持静态 `VP8 `、`VP8L` 和 `VP8X` 的规范尺寸字段及非空压缩数据；`VP8X` 动画标志或任意 `ANIM`/`ANMF` chunk 都作为动画失败。解析所得画布尺寸必须与内部 bitstream 及登记的 1600 x 1000 一致；错误签名、截断、非法 chunk 长度、无静态图像 bitstream 或尺寸不符均失败关闭。该解析只拥有 E-007 所需的容器、动画与尺寸门禁，不声称替代浏览器的完整像素解码或素材内容审核。
- 成功值是按 `projectId`、`sourcePath` 稳定排序并深冻结的 `readonly ProjectPreviewAsset[]`；每项只包含 `projectId`、登记 `sourcePath`、唯一派生的 `publicUrl = /assets/<sourcePath>`、`width`、`height` 与 `alt`。不得从文件名猜项目或公开 URL，不把 `publicUrl`、文件大小、哈希、审核状态或其他派生值回写注册表。`draft`、`planned` 未登记预览时不产生输出；所有状态一旦登记预览都必须通过同一字节和一对一门禁。

### CODE-006 静态渲染与客户端副作用

- 主站静态内容必须能在无运行时 API 的构建路径中完成渲染；页面不得靠客户端 fetch 才获得文章、项目或导航主体。
- 模块初始化和静态渲染阶段不得直接访问 `window`、`document`、浏览器存储或其他仅客户端对象。
- 获批的客户端行为必须放在明确的客户端边界内，并在 hydration 后执行；不得把第三方请求、数据采集或业务状态藏入通用布局组件。
- 按 E-004 优先使用 Docusaurus 官方配置、Infima 和 CSS；默认不 Swizzle、不 eject。#28 的 fit-gap 已按 E-004 证明默认 docs 左栏断点、全局抽屉归属与移动标题目录无法表达 D-034，因此允许同路径 `DocRoot/Layout`、`DocItem/Layout` 两个最小布局包装；关闭后复核又由实现前真实基线和锁定 Docusaurus `3.10.2` 源码共同证明 `Navbar/Layout` 没有 Escape 关闭路径，故只增加同路径最小包装，在 hydration 后监听 Escape、调用框架原关闭按钮并把焦点归还原 toggle，不复制导航结构或状态。扩大包装集合、读取第二内容源、增加客户端目录状态或改变框架导航状态机必须重新证明必要性。包装继续复用框架 breadcrumbs、正文、页脚和 paginator，并由构建契约与真实浏览器回归覆盖。

来源：D-027、D-029、D-051、D-053；[主站体验与内容架构](../product/site-experience.md)。

### CODE-007 React 组件职责

- 页面和组件只消费显式 props、Docusaurus 已验证元数据或获批上下文，不在渲染过程中解析源文件或重建领域校验。
- I-14 的 `SiteContentData` 展示契约只消费 `axial-muse-content-data` 插件公开的 `projectNavigation` 与 `writingNavigation`，在展示边界验证所需字段并按当前规范 pathname 查找详情；缺失、重复、未知详情或形状漂移必须抛出稳定、脱敏错误，不能退回正文字符串、原始注册表或旧页面。项目 `relatedWriting` 与文章 `relatedProjects` / `relatedArticles` 只允许 `{title, canonicalPath}` 安全链接，必须按显式源顺序、无重复地指向同批展示投影中标题一致且类型正确的当前可见目标；悬空、跨类型、标题漂移或未解析 ID 均失败关闭。`ContentMeta` 只在对应数组非空时显示“相关技术分享”“相关项目”或“相关文章”及其站内链接，不改变左侧规范归属。articleId、sourcePath、未解析关系 ID 或私有日期索引不得渲染为主视觉信息。
- 页面级 `<head>` 只由一个可复用 `SeoMetadata` 组件负责自定义覆盖。静态页面显式传入已在产品 Spec 固定的 title、两条 description 与 canonical path；详情页由同一安全展示投影提供这些值。组件从站点配置读取 canonical origin，统一输出 title、搜索 description、分享 description、canonical 与 Open Graph title/description/URL；只有输入含已审核站内图片时才输出绝对 `og:image`，不得猜测文件名、读取远程图片或生成占位素材。
- 可复用展示组件不得包含项目专属 API、身份、评论或上传逻辑；未来动态能力通过独立集成层进入。
- 普通 Markdown 不得导入组件；MDX 只能从 `src/components/mdx/index.ts` 的显式具名导出中引用仓库内组件，该入口就是首版机器白名单，不再维护第二份手工组件清单。新增导出必须在同一 PR 说明普通 Markdown 不足之处、是否 hydration、外部请求与失败表现；默认组件必须静态可读且不发起网络请求。
- 可复用组件模块使用具名导出；只有 `src/pages/` 文件路由入口与 `src/theme/` 主题覆盖按 Docusaurus 入口契约使用默认导出。每个复用组件位于 `src/components/<PascalCase>/`，实现为 `<PascalCase>.tsx`，局部样式为 `<PascalCase>.module.css`，按真实消费者需要建立 `index.ts`；hook 放在所属组件目录，只有跨组件复用时才进入 `src/components/hooks/`。

### CODE-008 样式与资源

- 组件必须消费经产品 Spec 确认的视觉令牌和响应式结果，不得在本规范复制色值、断点或排版数字。

### CODE-014 作者命令

- 新文章入口固定为 `node scripts/author/create-article.mjs --source-name <name> --title <text> --slug </writing/...> --summary <text> --author <id> --topic <id>`。`--author` 与 `--topic` 可重复，`--project`、`--module` 可选。M0 只创建 `index.md`，不提供 `--format` 或 MDX 快捷入口；未来 MDX 白名单出现真实获批组件后再扩展命令。
- 命令只接受完整非交互参数，先验证全部字段、注册表引用、目标目录不存在和精确 Node 版本，再取得排他作者锁并重新验证目标与当前工作区。随后只在内存生成 UUIDv7 并渲染完整模板，由冻结 frontmatter 解析器逐字段回读；CODE-018 的严格候选 API 只接收 `{articleId,sourceName}`，不得把其他字段塞入该身份接口或绕过 I-06 自建第二套整批 schema。完整历史与身份候选同时通过后才能创建同一文件系统内的 `site-content/.author-staging-*` 并写入完整 `index.md`。flush 文件、staging 目录和 rename 的 source/destination 两个父目录后，仍持有作者锁时必须由 I-06 与 E-013 从目标实际字节完成终态读回，随后删除 lock 才是 commit point。任一步失败都回滚目标、删除本次临时目录并释放锁；质量、预览和构建发现作者锁或残留 staging 时失败，不读取半成品。不得覆盖、修复或补写既有文章。
- draft 模板不填写 `publishedAt`，不从系统时间、UUID、标题或路径推导任何业务字段；`updatedAt` 也不由创建命令自动写入。命令不运行 Git add/commit/push，不调用发布、预览或构建，也不得被 CI、hook 或 Docusaurus 隐式调用。
- UUIDv7 文本校验同时检查规范小写连字符形式、version 7、RFC variant、当前树唯一和 Git 历史未复用；历史只读检查由 `scripts/quality/check-content-history.mjs` 统一拥有，创建命令调用 `scripts/quality/lib/content-history.mjs` 的同一候选校验，不复制正则、身份提取、父状态或 Git 扫描算法。
- 作者事务的固定互斥标记为仓库根 `.axial-muse-author.lock`，只保存本次随机 256-bit 小写十六进制 owner 并以私有普通文件身份持有；staging 名固定为 `site-content/.author-staging-<owner>`。命令不猜测或回收已有 lock/staging，发现任一残留即以 `AUTHOR_TRANSACTION_RESIDUE` 失败，交由作者先检查现场。正常失败只删除经 inode、owner 与预期成员重新证明仍属于本次事务的路径，不能递归删除已被替换或加入未知成员的目录；操作与回滚同时失败时内部用 `AggregateError([operationError,rollbackError])` 保留原对象并公开报 `AUTHOR_ROLLBACK`。该状态表示 D-065 原子性已遭文件系统故障或不遵守作者锁的同 UID 外部写者破坏，既不是允许残留的正常终态，也不得作为 #24 完成证据；必须停止后续消费者并人工核对现场。正常关闭证据必须证明所有注入失败均恢复调用前状态。
- 标准 Node/POSIX 目录 rename 没有 `RENAME_NOREPLACE` 接口，因此线性化边界明确依赖同一工作区的作者写操作全部遵守本 lock，命令不宣称抵御无视 lock 的同 UID 并发写者。受控边界内仍在加锁前、加锁后和 rename 紧前分别拒绝任意类型的既有目标，紧前检查发生在测试故障钩子之后；已有普通文件、符号链接、空目录和非空目录都不得被正常命令替换。作者 lock 建立后先 flush 仓库根；rename 后依次 flush `site-content/writing/` 与 `site-content/`、从目标实际字节运行 I-06/E-013、复核注册表快照和 lock 身份，再删除 lock；激活后任一步失败先证明目标仍属于本事务，再原子移回 staging 并精确清理。production build 先检查作者 residue，取得自身 build lock 后再次检查；作者命令也在取得作者 lock 前后拒绝 build lock，借此关闭两者各自 preflight 后的内容读写竞争窗口。
- `scripts/author/lib/transaction-state.mjs` 与 `scripts/quality/check-author-transaction.mjs` 只允许 Node 内置模块和只读 residue 检查，不得导入作者创建编排、I-06 loader、Docusaurus、E-013 或任何第三方包。零依赖 `quality` 只调用该 checker；production build 在内容读取前调用同一 checker，#8 的 preview 迁移也必须在任何 checkout 后内容扫描前复用它。真实 CLI、冻结 parser 和 E-013 集成验收不进入 `quality`、hook、共享 `test` 或最低 Node job；它只由精确 `.nvmrc` 主端点在显式作者验收命令下对临时完整 Git fixture 运行，不构成 CI 对真实工作区的隐式创建。

- 两份 SPDX artifact 先完整写入并 fsync 同一候选目录，根 `THIRD_PARTY_NOTICES` 另写入并 fsync 受控候选文件；发布器先验证旧三件套，再分别备份、激活并 fsync 两个父目录，激活后从磁盘重读三件套并调用同一供应链闭包检查器。旧 canonical 从读取 snapshot 前即持有 artifact 目录、两个子文件和 NOTICE 的原始 fd，rename 后把同一 ownership 转交 backup；候选文件也持续持有创建该 inode 的原始 fd，并在每次 `syncFile` 后立即以路径身份复核，不能关闭后重新收养。所有活动对象以 `dev`/`ino`/类型/所有者/链接数加完整字节快照复核；回滚不得对 canonical 路径直接 `rm`/`unlink`，而要先原子移入同父目录唯一 quarantine，再验证仍属本次候选。不同字节改写、同字节换 inode 或所有权检查后替换任一发生时，当前/隔离状态与旧备份均保留并报 `SPDX_ARTIFACT_PUBLISH_UNCERTAIN`。新三件套全部激活并复核后即进入 committed 状态；其后的旧备份清扫失败只保留完整 active canonical 与残余备份并报 uncertain，不再回滚成部分状态。只有提交前失败且全部已切换对象证明归属、恢复目标仍为空时才重建旧状态并清理 quarantine；首次发布失败才恢复为无三件套。内外两层生成锁都以 mode `0600` 独占创建并 fsync 文件和父目录；释放时先比较 canonical marker 与打开描述符的 `dev`/`ino`/类型/链接数，已被替换则原位保留并失败；一致时才原子移入同父目录唯一 quarantine、同步目录并再次比较，只有两次都确认仍是本任务锁时才删除。检查与 rename 之间发生的身份漂移保留在 quarantine 并失败关闭，不对未证明所有权的路径执行 `unlink`/`rm`。跨目录切换不具备真正文件系统原子性，任一活动路径仍可能在 rename 窗口短暂 `ENOENT`，纯 Node 也不能消除最后一次身份检查到文件系统操作之间的纳秒级窗口，因此生产与作者检查不得在生成期间并发读取或写入。

- 每个提交分别保存当前快照和从父提交合并的历史 ledger，不能用一次全局线性“最后看到”状态替代 DAG。source-name ledger 保存唯一 articleId，articleId 与注册表 ID ledger 分别保存首次引入 commit 作为 lineage origin；publishedAt ledger 按 articleId 保存首次出现的规范日期。ID 首次出现时记录当前 commit；从父历史继承时，全部非空父 origin 必须一致，平行分支独立首次引入同一 ID 因 origin 不同而失败，即使 merge 当前快照只保留一个。日期在任一父或当前快照首次出现后，后续仍存活的同一 articleId 不得删除或改值；merge 的多个非空父日期必须一致，一侧尚未发布时继承另一侧已经建立的值。合并父对同一 source-name 给出不同 articleId 时也失败；当前 ID 不在任何直接父快照但已在父 ledger 出现时判定为删除后重引。只要 articleId 仍在至少一个直接父快照中且 lineage 唯一，连续修改、正常 merge 和保留 ID 的原子目录改名可以继续；同一快照重复 ID 或 source-name 改绑仍失败。

### CODE-019 服务端重定向派生与 release 绑定

- `scripts/release/lib/runtime-redirects.mjs` 是 E-014 路径规范化、公开 HTML 路由提取、规则闭包、稳定序列化与 Nginx 渲染的唯一实现，并提供相邻 `runtime-redirects.d.mts` 供严格 TypeScript 构建适配只读调用。`scripts/release/package-site.mjs` 生成制品，`scripts/quality/check-release-package.mjs` 从原始输入独立重算；两者必须调用同一库，不复制正则、排序、链环检测或配置模板。相关 `.mjs` 均加入 `check:js` 明列清单。
- 生成入口只接受 realpath 后的 production `build/`、仓库固定 `docs/contracts/redirects.json`、精确 40 位 commit SHA 和站点配置中已经校验的 canonical origin；不接受 preview、任意 registry 路径、origin 覆盖、状态码、Nginx 模板或额外规则参数。它从根 `index.html` 与规范子目录 `index.html` 建立公开页面路由集合，单独识别并排除 `404.html`、静态资源和保留文件；每个注册表 `to` 必须一对一映射到当前 payload 页面，每个 `from` 对应的静态 HTML 必须不存在。

- `runtime-redirects.json` 只含 E-014 固定的三个顶层字段；每个 rule 只含按 `kind`、`from`、`to` 顺序序列化的三个字段。对象键固定顺序、数组按 source 排序、UTF-8、LF、2 空格和单个末尾换行；不读取系统时间，不写绝对路径、commit、`reason` 或摘要。Nginx 文件按相同规则顺序为每条规则生成固定三行 block：exact `location` 起始行、2 空格缩进的 `return 301` 行和闭合行，block 之间不插入源文本；目标 origin 使用已校验常量，查询只通过字面 `$is_args$args` 保留。禁止注释、regex、`map`、`if`、`$host` 或 server 级 `return`。
- `package-site.mjs` 在复制完成且源 build 未变化后生成两个派生文件，再把源注册表原始字节摘要、按公开路由排序后的集合摘要、两个派生文件摘要和规则数写入 `release.json`；`files.sha256` 覆盖 payload 与两个可部署文件。检查器必须重新读取 build 和源注册表生成期望字节，验证 registered 与 canonical-slash 数量、全部摘要和 source 静态页面缺失，并拒绝手工修改 metadata 后自洽但不再可从源重建的 artifact。
- 服务器安装契约不允许重新解释 `redirects.json` 或运行仓库 Node.js：固定发布脚本只校验并复制两个已绑定文件到 release 的非 Web Root `config/`，再生成只含精确 SHA 绝对 payload root 与同 SHA include 的 `site-release.conf`。root-owned `/var/lib/axialmuse/url-exposure-ledger.json` 是独立于 release 的只追加生产证据；固定部署实现必须用结构化 JSON 解析维护它，只接受 E-014 的 `publishedRoutes` 和 `kind: "registered"` 历史边，`canonical-slash` 不入边账本。实现必须拒绝未知字段、非法路径、非 40 位 SHA、重复记录、删除或改写既有记录，并以同目录临时文件、flush 文件与父目录、原子 rename 更新。账本不得进入 artifact、Web Root 或仓库编辑源，也不得从当前配置、注册表或单个 release 自动重建；实施服务器所用的具体结构化解析工具属于服务器软件安装，仍须按部署文档现场核验和授权。
- 兼容检查复用 CODE-019 的路径与 runtime manifest 解析，但不生成或改写候选规则。对候选 payload/rules 定义最多一步的 `resolve(path)`：200 route 返回自身，exact source 返回其当前 200 target，其他失败；账本中每个历史 published route 必须可解析，每条历史 registered edge 的 `from` 与 `to` 必须解析到相同终点。新边可以把既有 source 改指新的最终页面，但旧 target 必须继续为 200 或成为直达同一终点的 source。候选配置先在隔离本机 Nginx 监听地址完成全规则 HTTP 测试；随后把候选全部规范 200 路径和新增/改指的 registered 边作为潜在暴露原子并入账本，再切 `current`、`nginx -t` 和 reload；这使 `canonical-slash` 的 target 也在公网可缓存前得到保护。只有预先选出的 fallback release 也通过并入后账本时才允许自动回滚；没有兼容 fallback 的候选默认失败，显式生产授权选择 forward-only 后，reload 或公网冒烟失败必须保持兼容闭包并向前修复。公网冒烟与账本备份记录都成功后才能标记 deployment 成功。

### CODE-020 production build 字节所有权与最终 artifact

- `production-artifact` 是 E-015 唯一可部署 build producer，必须是非 matrix、无 environment、无 repository/environment Secret 的单 job。它与四个 prerequisite job 的 `permissions` 只允许 `contents: read`，未列权限均为 `none`；不得授予任何 write、OIDC 或 attestation scope。它不得配置 `actions/setup-node` cache、调用 cache restore/save Action，或读取任何跨 step、跨 job、跨 run 共享或复用的依赖/build cache；E-010 为本次 job 新建且不复用的私有 npm cache 是冻结安装的必需隔离目录，不属于被禁缓存。workflow 静态门禁要求它直接 `needs` `website-quality`、`node-minimum`、`diagrams`、`supply-chain`，不得使用 `always()`、`continue-on-error` 或自写表达式把非 success 转成可运行；触发谓词只允许 canonical repository 的 `push` `refs/heads/main`，以及保留人工入口时 canonical repository 的 `workflow_dispatch` `refs/heads/main`。PR、fork、Dependabot、`dev`、tag 和其他 dispatch ref 不得生成最终 artifact。
- fresh runner 的 checkout 必须显式精确 `github.sha`、`fetch-depth: 0`、`persist-credentials: false` 且无 partial/sparse 选项；随后验证 `HEAD` 和事件 SHA 相等，并在安装前要求 checkout 中不存在 `build/`、`dist/`。Node/npm 只读 `.nvmrc` 和已准入随附版本；E-010 `ci` profile 使用全新 HOME/config/cache 冻结安装并验证 `package.json`、`package-lock.json` 前后摘要不变，不恢复依赖或 build cache。缺失 lock、浅历史、预存输出、安装失败或任何漂移都失败。

- `scripts/quality/lib/file-tree.mjs` 唯一拥有 E-015 release 身份使用的规范 `AXIALMUSE-FILE-TREE-V1` wire format 与整树 release digest 算法，即 `sourceBuildTreeSha256` 和 `releaseContentSha256`；为生成或验证这两项摘要，它枚举对应 build/release 树，只接受上述 CODE-015 上限和 Unicode 15.0 assigned repertoire 内的规范相对 POSIX 普通文件，拒绝符号链接、硬链接、特殊文件、隐藏 path segment、非 NFC/非法 UTF-8、绝对或父级路径、控制字符、重复规范化路径和大小写冲突，并按路径原始 UTF-8 字节无符号字典序排列。树摘要输入先写入 ASCII `AXIALMUSE-FILE-TREE-V1` 和单个 `0x00` byte，再顺序写入 records，最后对完整输入计算 SHA-256；每条 record 精确为 8-byte big-endian unsigned path byte length、path UTF-8 原始字节、8-byte big-endian unsigned file byte length、32-byte raw `SHA-256(file bytes)`，摘要输出为 64 位小写十六进制。mtime、uid/gid、mode 和空目录不是内容身份；同一库另行捕获但绝不序列化目录/文件的 `dev`、`ino`、类型、链接数、size、mtime 与 ctime 操作证据，用于发现 A→B→A、同字节新 inode 和整树替换。服务器最终统一目录 `0755`、文件 `0644`。CODE-015、CODE-019、#33 的封装器与独立 release 检查器凡生成或验证上述两项规范摘要，都必须调用该库，不复制 wire format、record 排序或整树摘要算法。I-12 的 production checker 仅为 E-008 的静态素材泄漏、SSR 图片属性引用和逐文件路径/长度/SHA-256 证据而枚举 build；它不生成 `AXIALMUSE-FILE-TREE-V1` records、`sourceBuildTreeSha256`、`releaseContentSha256`、`files.sha256` 或 release metadata，也不能替代 #33。这里的“唯一”仅限仓库内规范 release 实现；跨 TAT 信任边界故意保留第二个 root-owned 服务器 verifier，它不运行或导入仓库 Node 模块，而是按上述 wire format 独立实现。两端必须共享至少空树、空文件、非 ASCII UTF-8 path、多文件原始 byte 排序、单字节变化和 Unicode 版本漂移拒绝的固定 golden vectors；任一端不接受全部相同向量和负面路径 fixture 就不得接线，借此防止双实现漂移。

- 服务器 verifier 必须先从解包后全部 release 普通文件独立重算并比较 artifact 外传入的 `releaseContentSha256`，再解析内部自报字段；另从 `payload/` 重算 `sourceBuildTreeSha256` 和公开 HTML route 集合/`AXIALMUSE-PUBLIC-ROUTES-V1`，逐项核对 `files.sha256` 的规范字节、精确成员集合与逐文件摘要，以及 `release.json` 的闭合 schema、固定 repository/payload root、显式 commit、摘要和 count。它严格解析 `runtime-redirects.json`，证明每个 registered source 的带/不带斜杠双形式、每个非根公开 route 的完整 canonical-slash、唯一 source、无链/环/自跳、target 为当前 200 且 source 不是页面，再从该结构独立渲染固定三行 Nginx block 并逐字节比较。`redirectRegistrySha256` 因源注册表按 CODE-019 不进入服务器，只校验裸摘要形态并由已经外部认证的完整 release digest 绑定；不得把它报告为服务器从源码复算。全部验证后必须在 SIGINT/SIGTERM 屏蔽区内再捕获候选、用 Linux `renameat2(RENAME_NOREPLACE)` 激活并从正式路径重算完整树；rename 前后的 bytes 和非根 inode 操作证据不一致、目标已出现、父目录身份漂移或同步失败均不得成功。成功 stdout 精确为单行 JSON 与 LF，固定返回 commit、双外传摘要、payload/route/runtime/Nginx 摘要、release/payload/route 文件计数和三类规则数；成功行与 committed 状态位于同一不可取消线性化区，期间到达的中断在 commit 后按成功处理，之前的中断保持稳定失败。失败 stdout 为空、stderr 只输出稳定 `SERVER_ARTIFACT_*` code、仓库相对逻辑定位和中文消息，不含 traceback、绝对 staging 路径或 archive 原字节。发现入口前已经存在或竞态出现的 `verified-release` 必须原样保留并失败；本事务在激活前失败不得产生正式输出，激活后失败只可清理仍与候选 ownership identity 一致的输出，身份不确定时保留现场并报 cleanup 错误。
