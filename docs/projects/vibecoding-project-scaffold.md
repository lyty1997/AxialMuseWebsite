## 解决的问题

新项目在使用 AI 编码工具时，容易只关注生成代码，而缺少稳定的项目定位、设计真相源、执行规则、质量门禁和可追溯工作流。该脚手架提供一套可初始化的仓库基线，使项目从第一天开始就能约束文档、代码、CI 和 Agent 行为。

它不替代具体应用框架，也不承诺自动生成完整产品。使用者仍需根据真实项目决定前端、后端、数据库、部署和内容边界，并先在 `docs/` 记录决策。

## 已验证能力

- 通过 `scripts/init.mjs` 替换项目名、品牌、slug、定位和许可证归属等占位内容。
- 提供 `AGENTS.md`、`CLAUDE.md`、`codex-rules/` 和 `docs/`，建立设计先行与公开内容约束。
- `npm run quality` 检查 JavaScript 语法、Markdown 链接与索引、契约词表、常见密钥形态和静态站点入口。
- GitHub Actions 在主分支和开发分支运行质量门禁，并覆盖 Ubuntu 与 Windows。
- 提供 pre-commit 和 commit-msg Git hooks，使本地提交约束与 CI 对齐。
- 提供 PlantUML 编译与渲染工具，以及按项目需要采用的技术栈配方。
- 提供跨机器同步和远程预览脚本；具体环境仍需使用者自行配置并验证。

公开描述只能使用仓库当前存在并可核对的能力。不得写成“适用于所有项目”“自动保证代码质量”或“无需工程经验即可生产上线”等无法验证的承诺。

## 视觉证据

主站实现时优先使用项目自身的真实证据，不使用泛化的 AI 机器人或抽象科技素材。候选方案按优先级排列：

1. 初始化命令运行前后的真实终端画面，使用专门创建的无敏感示例目录。
2. 仓库目录结构与质量门禁通过结果的组合截图。
3. GitHub 仓库公开页面截图，但需避免出现私人通知、登录状态或浏览器扩展信息。

截图发布前移除本机用户名、绝对路径、IP、远程地址中的凭证、通知和其他隐私信息。图片应提供有意义的替代文本，并保留原始截图来源与制作日期。
