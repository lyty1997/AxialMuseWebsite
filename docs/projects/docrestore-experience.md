## 目的

本文定义 DocRestore 在 Axial Muse 主站中的公开展示方式，并保留未来重新评估在线体验时的技术与安全门禁。DocRestore 将文档照片经过 OCR、清洗、去重、可选 PII 脱敏和 LLM 精修后还原为 Markdown。

用户已确认首版不提供在线体验。主站首次上线只展示项目说明和公开 GitHub 仓库，演示视频在素材完成后作为增量增强；不部署 DocRestore 前端，不公开后端，不创建项目或 API 子域名的 DNS、Nginx、证书和健康检查。体验注册表保留 `docrestore` 名称用于避免后续冲突，并以 `status: planned`、`dnsProvisioning: disabled` 明确禁止实施。

## 演示视频契约

主站只在真实视频、封面和字幕全部就绪后显示播放器，不展示空播放器或“即将上线”占位。后续增加视频时使用原生 `<video>`，不嵌入第三方 iframe，不自动播放，不引入统计或追踪脚本。

推荐素材：

| 资产 | 契约 |
|---|---|
| 视频 | MP4，H.264/AAC，720p 或 1080p，2-4 分钟，压缩目标不超过 30 MiB |
| 封面 | WebP，16:9，清晰展示实际界面，目标不超过 250 KiB |
| 字幕 | UTF-8 WebVTT，至少提供简体中文字幕 |
| 文本摘要 | 说明输入、处理步骤、输出和演示环境边界，不宣称未验证能力 |

页面播放器使用 `controls`、`preload="metadata"` 和 `playsinline`，设置稳定的 16:9 尺寸，避免加载时布局跳动。视频加载失败时保留项目说明和 GitHub 链接；播放器本身不替代文字版项目介绍。

录制只能使用专门制作的无敏感样例，不使用真实用户文档、客户资料或个人隐私。发布前逐帧检查并移除：

- API Key、Token、Cookie、密码、二维码和浏览器自动填充内容。
- 本机用户名、绝对路径、内网/公网 IP、终端历史和通知弹窗。
- 第三方文档、未授权图片、真实姓名、联系方式和其他 PII。
- 可能让观众误认为已经提供公网服务的域名、登录或在线上传画面。

媒体初期可随主站静态产物发布；上线前根据成片大小和轻量服务器套餐流量复核。若实际访问量或文件大小不适合随站托管，先更新部署与隐私文档，再迁移到腾讯云对象存储或其他明确来源；不得临时改用带追踪的第三方嵌入。

## 未来在线体验拓扑（暂不实施）

```text
浏览器
├── HTTPS ──> docrestore.axialmuse.com
│             └── 上海轻量服务器 / Nginx / 静态 frontend/dist
└── HTTPS/WSS ──> api.docrestore.axialmuse.com
                  └── 独立后端入口 / FastAPI / OCR / 数据存储
```

- 只有用户重新批准在线体验且未来上线门禁全部通过后，`docrestore.axialmuse.com` 才使用显式 DNS A 记录指向上海轻量服务器。
- `api.docrestore.axialmuse.com` 是建议的 API 主机名，使用独立 DNS、TLS、反向代理、限流和运维责任；其目标地址在后端服务器确认后登记，不写入项目体验注册表。
- 浏览器直接连接独立后端，避免最大 50 MB 单图片、200 MB 单 PDF、结果下载和长连接流量绕行轻量服务器。
- 上海轻量服务器反向代理 `/api` 仅作为备选方案；采用前必须确认套餐带宽与流量、上传超时、WebSocket、故障影响和日志边界，不作为默认生产方案。
- 前端和 API 不共享跨子域 Cookie。若后续采用 Cookie 会话，Cookie 必须限定 API 主机，不能设置 `Domain=.axialmuse.com`。

## 未来前端适配契约

当前前端将 API 固定为相对路径 `/api/v1`，WebSocket、图片和下载 URL 也基于当前页面主机；这只适合 Vite 本地代理或同源反向代理，不能直接连接目标拓扑中的独立 API 主机。

DocRestore 仓库在任何在线体验生产发布前必须完成以下改动：

1. 新增经过 URL 校验的构建期 API Origin，例如 `VITE_DOCRESTORE_API_ORIGIN=https://api.docrestore.axialmuse.com`；生产构建不得回退到未确认地址。
2. REST、上传、预览图片、结果下载和 WebSocket 统一由同一个 API URL 构造器生成，禁止各模块分别拼接主机名。
3. 生产环境只允许 `https:` 和 `wss:`，开发环境例外必须显式限定在 localhost。
4. 构建产物不得包含 API Key、静态 Bearer token、后端服务器 IP 或其他 Secret；Vite 暴露到客户端的环境变量只能保存公开配置。
5. 为跨域 REST、上传、下载、401/403、WebSocket 断线重连和生产 API Origin 增加测试。
6. 体验页提供返回 Axial Muse 主站项目说明的入口，并展示 `沪ICP备2026029086号`；备案适用范围仍需在上线前核验。

## 身份与授权边界

当前 `DOCRESTORE_API_TOKEN` 是单个设备/服务级 Bearer token，不是用户登录系统。前端把 token 存入 `localStorage`，部分图片、下载和 WebSocket URL 还会把 token 放入查询参数；后端任务列表、文件浏览和结果接口也没有按用户隔离。因此，现状只适用于受控的单用户部署，不能作为公网多用户登录能力上线。

公开体验至少需要：

- 明确真实用户身份、注册或邀请范围、登录、退出、会话过期和账号删除流程。
- 所有任务、上传会话、源文件、结果、历史记录和下载按用户或租户强制授权，不能只在前端隐藏。
- 禁止在 `localStorage` 保存长期认证 token；优先使用 `Secure`、`HttpOnly`、适当 `SameSite` 的 host-only 会话 Cookie，或经独立评审的短期内存凭证。
- 禁止把认证 token 放在 URL 查询参数；图片、下载和 WebSocket 改用不会进入 URL、浏览历史或常规访问日志的授权方案。
- 禁用公网用户的服务器目录浏览、任意服务器路径输入和源文件 staging，除非已经设计独立沙箱与逐项授权。
- 对登录、任务创建、上传、下载、WebSocket 和高成本 OCR/LLM 操作配置用户级速率限制、并发限制和资源配额。
- 后端 CORS 只允许精确来源 `https://docrestore.axialmuse.com`，不使用通配符；WebSocket 同样校验精确 `Origin`，并在会话失效时关闭连接。

OWASP 建议不要在 `localStorage` 保存会话标识，文件上传应同时执行身份授权、类型与签名校验、大小限制、存储隔离和滥用防护，WebSocket 应使用 WSS、校验 `Origin` 并实施连接与消息级授权。参考：[Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)、[WebSocket Security](https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html)。

## 文件、隐私与 LLM 数据边界

上传材料可能包含身份证明、合同、内部文档、源代码或其他个人与商业敏感信息。公开前必须形成用户可见且与实现一致的数据说明：

| 边界 | 上线前必须确认 |
|---|---|
| 收集内容 | 图片、PDF、文件名、任务配置、处理结果、诊断信息和必要技术元数据 |
| 用途 | OCR、文档还原、用户预览、编辑与下载；不得默认用于训练或其他目的 |
| 存储位置 | 后端服务器地域、上传临时目录、SQLite/数据库、结果目录和备份位置 |
| 保留周期 | 上传会话、失败任务、成功结果、备份和安全日志分别定义期限 |
| 删除与导出 | 用户可删除自己的源文件、任务和结果，并能导出处理结果；删除须覆盖派生文件和到期备份策略 |
| 第三方传输 | 云端 LLM 的供应商、处理地域、发送字段、PII 脱敏发生顺序和用户明确选择 |
| 本地处理声明 | 只有 OCR、LLM 和存储均实际在受控本地环境时，才能宣称“数据不出本地” |
| 凭证责任 | 明确使用站点统一 LLM 凭证还是用户自带 Key，不允许浏览器长期保存用户 API Key |
| 滥用防护 | 文件数、单文件、单任务、每日用量、并发、磁盘总量、GPU 时间和异常下载限制 |

当前后端已存在单文件大小限制，但单文件限制不能替代用户级总配额、并发控制、磁盘水位保护和过期清理。对浏览器中“记住配置”持久化完整 LLM 配置的行为，公网版本必须移除 API Key 持久化或改为不会向前端回传明文的服务端凭证托管方案。

## 后端生产基线

独立后端不是本主站轻量服务器的附属目录，需要单独完成：

- 明确服务器地域、运营主体、域名解析、TLS、备案/接入要求、到期与续费、备份和恢复责任。
- 后端应用只监听内网或 loopback，由受维护的反向代理公开 443；不得直接暴露开发服务器端口。
- API 健康检查与 GPU/OCR 就绪检查分离，避免应用存活掩盖处理能力不可用。
- 使用 WSS，设置请求体、连接、空闲和处理超时；上传采用流式写入、文件签名校验、随机服务端文件名和隔离存储。
- 日志默认不记录 Authorization、Cookie、查询 token、API Key、上传正文和文档内容；错误追踪只保留必要元数据并按期限删除。
- 建立磁盘、GPU 显存、任务队列、失败率、证书、后端可用性和外部 LLM 依赖监控，并验证告警接收。
- 进行两次连续版本发布、应用回滚、数据库/结果恢复和用户数据删除演练。

若后端位于中国大陆，上线前核验该主机与 API 域名的备案接入及服务内容；若后端或 LLM 位于中国大陆以外，必须在隐私说明和架构评审中明确跨境传输与适用合规边界。

## 当前主站展示流程

1. 使用无敏感样例在私有环境录制 DocRestore 完整工作流。
2. 完成视频压缩、封面、中文字幕和文字摘要。
3. 执行逐帧隐私、凭证、版权和公开表达审核。
4. 将媒体资产加入主站受控目录，并在内容数据中记录仓库、视频、封面和字幕路径。
5. 实现主站项目说明、GitHub 链接和原生视频播放器，不创建体验链接。
6. 验证视频键盘控制、字幕、加载失败回退、移动端和桌面端布局。
7. 运行主站完整质量门禁，经人工预览后随主站正常发布。
8. 上线后检查媒体流量；超过服务器预算时先评审媒体托管迁移方案。

## 未来在线体验门禁

本节当前冻结，不属于 M0 发布范围。只有用户明确重新批准在线体验后，才能恢复子域名、前端和后端实施，并逐项满足以下条件：

- 外部后端主机名、地域、负责人、容量、备份和备案边界已登记并核验。
- 真实多用户身份与服务端授权已完成；若只做邀请制单用户体验，页面和访问控制明确限制范围。
- 用户数据在任务、文件、结果、列表、下载和 WebSocket 全链路隔离。
- 认证 token 与 LLM API Key 不进入 URL、静态产物、持久化浏览器存储或普通日志。
- 上传类型、文件签名、单文件限制、用户总配额、并发、过期清理和磁盘保护均有自动测试或演练证据。
- CORS 与 WebSocket Origin 只允许登记的 HTTPS 前端来源。
- 用户已能查看数据用途、第三方 LLM 传输、保留周期，并完成导出和删除。
- 前端质量门禁、生产构建、两次连续部署、回滚、HTTPS 与跨域端到端测试全部通过。
- 主站和体验页只陈述已经验证的能力，不把计划能力写成已交付事实。
